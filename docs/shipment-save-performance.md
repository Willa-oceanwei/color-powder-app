# 出貨單儲存後的讀取與計時

儲存成功後，畫面直接顯示 repository 回傳的已提交單據（含版本、明細及金額），
不立即重讀完整清單或同一筆單據。客戶顯示名稱沿用此次編輯已讀取的資料。
列印與隱藏金額設定不會因此觸發清單或單據讀取。

按上一筆／下一筆時才載入清單，依原排序定位目前單據與相鄰單據；載入後恢復
原有的頁數及邊界停用狀態。尚未載入清單時，工具列顯示「已儲存」，不顯示虛假的總筆數。
查詢、重讀資料、開始新增／修改及作廢會退出這個儲存結果畫面。
手動重讀能看到其他使用者的更新；既有版本衝突檢查與報表快取失效邏輯維持原設定。
儲存失敗不會建立成功結果，也不會清除草稿。

Streamlit Cloud 的 Manage app → Logs 可搜尋 `diag=shipment-save-v1`：

- `shipment_save`：repository 儲存、提交及回讀已提交單據的總耗時。
- `shipment_read`：快取未命中或編輯快照首次載入的讀取耗時；`read_kind` 區分清單、單據、客戶、歷史價格與貨品選項。
- `shipment_render`：出貨單頁每次執行的總耗時；`outcome=interrupted` 代表被重跑或中止，並非已完成畫面。

紀錄只有階段、耗時、讀取類別、品項筆數及結果，不含客戶、單號、單據內容或憑證。
這次減少儲存後的同步讀取；儲存交易本身及其他頁面的慢查詢仍需依實際紀錄評估。
